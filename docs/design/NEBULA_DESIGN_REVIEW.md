- P1（Bottom Player）验收时，旧 UI 的遗留问题严重污染了新组件，视觉远未达预期，用户及时停手，决定先重做全局 UI 语言。

## 1. 项目理念：Nebula 是什么

**一句话**：Nebula 是一个可以走进去的音乐空间。曲库不是一张表，而是一片星云——每首歌是一颗带封面的星；你在其中漫游、拾取、聆听；音乐响起时，空间被它的颜色照亮，歌词在空气里流过。

**为什么视觉是核心**：播放器在功能赛道已经饱和，Nebula 的差异化只能来自"第一眼就被打动"的视觉与空间体验（同类参照：Mineradio、Folia）。

**三种状态（同一个空间的三种心境）**

| 状态 | 主角 | 其他元素 |
|---|---|---|
| 漫游 Browse | 星云（封面卡片） | 歌词退后（弱化）；界面安静 |
| 聆听 Listen | 音乐带来的环境光 + 歌词 | 星云仍在，但让出注意力 |
| 沉浸 Immerse（Listening Space） | 歌词 / Orb | 主舞台退场（模糊、变暗、降饱和） |

这与播放器母稿"主舞台退场""Complexity is controllable by the user"一致。

## 2. 现状诊断（实测证据）

勘察方式：用网易云热歌榜真实数据（40 首，真封面 / 真歌词）注入构建产物，无头 Chrome 拍摄 30+ 张界面与状态截图、2× 放大 hover 细节，并做对照实验。截图仅用于审查，不交付。

### 2.1 塑料感的四个物理原因

1. **面是"刷"出来的，不是"透"出来的。** 播放器底 `--mat-bg: rgba(26,30,50,.34)`（海军蓝）+ `blur(28px)` + 渐变高光（`src/styles.css:1233` 起）。背景切到浅色封面时，播放器、设置面板依然是同一块海军蓝板——不随环境变化，眼睛就判定为"有颜色的塑料"。真玻璃的三个标志：几乎不着色、背后的东西在边缘被弯折、轮廓靠亮边勾出。
2. **卡片是相框。** `.music-card`（`src/styles.css:269` 起）在封面外套 10px 灰色渐变厚框 + 三层投影 + 斜向反光 + 背面错层基座。封面是软件里最美的资产，被装进了灰色塑料托盘。
3. **焦点卡片是糊的（对照实验确认）。** 鱼眼景深给每张卡都加 `filter: blur(var(--blur))`，正中央那张也有 `blur(0.66px)`；滤镜让卡片先按小尺寸栅格化再放大 ~1.6×。去掉滤镜后中央卡片明显变清晰（已排除封面分辨率——原图 500px——与 `will-change` 两个原因）。
4. **主播放键是平涂灰色实心圆。**

### 2.2 "乱发光"的来源（实测确认）

`src/styles.css:3733` 与 `src/styles.css:4035` 两条全局规则，对**所有** `button` / `.glass-btn` / `[role=button]` 的 hover 施加 `box-shadow: 0 0 14px rgba(glow) + inset 0 0 0 1px` 与 `filter: brightness(1.16)`。P1 新组件虽写了"去圆形背景 / 去方框"，这两条规则依然层叠上去：

- hover「音质」→ 徽章外再长出一个发光胶囊（徽章本身也是带边框的胶囊，形成胶囊套胶囊）；
- hover「下一首」「播放模式」→ 发光圆盘；
- hover 歌名 → 发光方框。

这就是"新组件被旧 UI 污染"的字面含义：CSS 层叠。根治方式不是在新组件里再加覆盖，而是删除全局规则、改为组件自带的状态语言。

### 2.3 其他遗留问题

| 问题 | 位置 |
|---|---|
| 调试面板常驻正式界面（绿色等宽字：来源 / YRC / QRC / 逐字），并压住「回到中心」 | `src/App.tsx:550`（注释写着"临时，发布前删除"） |
| 点击卡片播放会自动弹出旧二级播放页（含已废弃的 ❤ 收藏按钮，封面位为空唱片） | `src/hooks/stage/useStage.ts:374` |
| 音质徽章文字被截断为 "stand…" / "exhig…" | `QualityControl.tsx` |
| Z1 歌词与 Z2 卡片抢同一片空间，句子常压在卡片边缘；白色粗体 + 阴影在浅背景上可读性弱 | `LyricsLayer` |
| 背景"跟随封面"= 封面放大模糊压暗铺满，浅色封面时变成一片脏灰 | `BackgroundLayer` |
| 海军蓝夜空 + 星点，有"屏保"感；每个面板各有一个底色，不在同一套光照里 | 全局 |
| `.glass-btn` 定义了 3 次（`styles.css:823 / 2470 / 2510`），全局规则相互覆盖 | `styles.css` |

体量参考（GPT 侧旧 UI 判定表实测）：样式表 6403 行、814 条规则、797 处颜色字面量、124 处圆角（13 种取值）、61 处阴影、19 处 z-index。

### 2.4 必须保住的资产

- **星云概念本身**：数千封面漂浮的 3D 空间 + 鱼眼 + 无限漫游——同类产品没有。
- **卡片 hover 动作**：转正、放大、去模糊、浮出播放键——动作本身是好的，问题只在材质。
- **Z1 三身份穿梭歌词的运动逻辑**（十几轮打磨，`LYRICS_SYSTEM.md`）。
- **Dock 小球 → 胶囊 → 窗口**的展开动作。
- **系统取色管线**（`palette.primary` / 三色歌词赋色）已存在。

## 3. 参照分析

### 3.1 Mineradio（读其源码文档 + 网页版）

- 所谓"全局玻璃"的配方：**SVG 位移贴图让背景在边缘弯折 + RGB 三通道错位的轻微色散 + 几乎为零的着色（≈10% 黑）+ 一圈内发光亮边**，通过 `backdrop-filter: url(#filter)` 施加（仅 Chromium 支持；Electron 可用）。
- 其作者明确否决的东西与 Nebula 用户的反感几乎一致："普通毛玻璃，没有扭曲质感""中间糊成一团""大面积白色渐变扫过去的廉价质感"。
- "深幽"来自：接近纯黑的底（不是海军蓝）+ 低饱和的青 / 金点缀 + 大幅图片 + 英文小号字距标签。
- 值得学的工程纪律：材质参数写成具体数值 + 黑底 / 亮底双背景验收清单。
- 许可证 GPL-3.0：**只借鉴思路与参数量级，不搬代码**。

### 3.2 kube.io《Liquid Glass in the Browser》

- 用斯涅尔定律从"表面高度函数"（推荐 convex squircle 轮廓）推出边缘折射位移，编码成 R/G 通道位移贴图，交给 `feDisplacementMap`；再叠一层按法线与光向计算的高光。
- 关键结论：**在 Chromium 里液态玻璃现在就能做**（Electron = Chromium），不必列为"未来"。
- 代价：位移贴图须与元素尺寸匹配，尺寸变化需重算（需缓存 / 只对稳定尺寸的面使用 / 动画期间降级）。

### 3.3 Folia（读其仓库与 9 张主题预览）

- 每个歌词主题是一整套"场景"：字体 + 布局 + 背景 + 动效共同设计（Fume / Lumi / Cad / Pat 的逐字编排，时计的表盘弧线排布，镜台的 3D 点云，群唱的对话气泡）。
- 歌词用衬线体（Noto Serif SC），界面用无衬线（Inter）；冷色深底上**只有正在唱的那个字**是暖金色并带柔光——单一强调色、只给一个字。
- 界面极度后退：播放条是底部很小的胶囊，翻译是暗色小字，背景只有淡淡的几何图形。
- 许可证 AGPL-3.0：同样只借鉴思路。

### 3.4 参照合并结论

Mineradio 给的是**材质**（光学玻璃 + 深幽底色），Folia 给的是**歌词**（排版即表演 + 单一强调）。这正对应用户在 Nebula 里最想要的两样：液态玻璃，与惊艳的歌词。

## 4. GPT 全局母稿审查（`NEBULA_GLOBAL_UI_MASTER.md` v1.3）

已读：系统总纲、十条根原则、§3 规范层全部（D1 数值表 / D2 组件清单 / C1–C10 组件规格）、§4 执行清单、G21 原文、状态账本、旧 UI 判定表。领域规则书（§2 A–T）未逐条通读。

### 4.1 总体判断

1. **方法错位**：用 133 道抽象选择题追问审美，用的是用户最弱的通道（语言描述），而用户最强的通道是"看到实物后的判断"。证据：用户此前对着真实界面给出的反馈（hover 轻微放大、玻璃要通透、拒绝黑塑料）与母稿 G21"hover 默认不 scale"相反——冲突时应以对实物的判断为准。
2. **133 题全选 D**，D 多为"Contextual …（视情况而定）"。听起来最成熟，实际是把真正的视觉决定推迟给执行者——旧 UI 失控（797 个颜色、13 种圆角）正是这样发生的。
3. **它是一套称职的"深色生产力工具"设计系统**（Linear / Vercel 一路）：中性灰阶、实色表面 N2/N3、1px 白边、13px 正文、8px 圆角按钮、粉色强调。**规范层几乎没有玻璃**——卡片、菜单、弹窗、输入框全为不透明实色底；照此执行，"塑料感"会变成"更整齐的塑料"。
4. **它不是看着 Nebula 设计的**：页面标题、48px 顶部导航、三栏布局、1440 容器、断点——而 Nebula 没有页面，它是一块空间画布 + 悬浮控件。
5. **封面取色被压得过死**：混入应用底 ≤16%、饱和度 ≤55%。对"音乐改变空间"的产品，这把音乐本身的颜色挡在了门外。

### 4.2 逐项处置（初判）

| 处置 | 内容 |
|---|---|
| **保留** | 离散几何家族（Radius R0–R4/R∞、Spacing S0–S7）· 时长 / 缓动分档 · Z-index 治理表与"组件不得私设层级" · 焦点与键盘可达（L 域）· 浮层生命周期与焦点恢复（S 域）· 对比度闸门 · 发光权（G133：发光必须有语义）· 表达预算（G68）作为概念 · "Specific beats General" · 旧 UI 判定表的实测数据与 P0–P3 批次思路 |
| **修改** | 中性色：海军蓝倾向的 N0–N8 → 真中性近黑，冷暖由环境决定 · 表面：实色 N2/N3 → 光学材质预设（见 §6.2）· 强调色：固定粉 `#FF8FA3` → 环境取色强调 + 中性兜底 · 环境色上限：16% / 55% → 大幅放宽，可读性闸门保留 · 排版：增加 Display / Lyric 角色（衬线），正文档位可沿用 · Hover：允许"图形自身"微放大（≤1.06，只作用于图标 / 文字，不作用于容器） |
| **删除** | 页面 / 顶部导航 / 三栏 / 断点等"网页应用"结构 · Q1–Q151 探索素材的任何引用 |

## 6. 设计方向（假设，待样张验证）

### 6.1 六条原则（审查稿版本）

1. **颜色来自音乐**：界面本身无色（中性光学材质），一切色彩来自当前封面 / 背景采样的环境光；强调色也从封面里取。
2. **玻璃是光学，不是油漆**：材质由物理参数定义（散射、折射、色散、亮边、着色），禁止"刷一层带色半透明底"。
3. **一次只有一个主角**：星云、歌词、面板之间按状态交接注意力（§1 三状态）。
4. **深，而不是暗**：近黑底 + 远 / 中 / 近三层景深；景深靠光的衰减与空气透视表达，焦点区不加模糊。
5. **安静的界面，响亮的时刻**：界面默认不发光、不乱动；把表达集中在少数"签名时刻"——星云本身、卡片浮起、播放态环境光、歌词。
6. **字是声音的形状**：歌词排版是一等设计面（衬线 Display + 单字强调）；界面文字用无衬线、克制分级。

### 6.2 一个材质模型，两个预设

现实中磨砂玻璃与透明玻璃是同一种材料，差别只在表面粗糙度。因此 Frosted 与 Liquid 不是两套样式，而是同一光学模型的两组参数：

| 参数 | 含义 | Frosted（初值） | Liquid（初值） |
|---|---|---|---|
| tint | 着色（中性黑 / 白） | 4–8% | 0–6% |
| diffusion | 散射（blur） | 14–20px | 0–2px |
| refraction | 边缘折射位移 | 0–6px | 20–40px（bezel 16–24px） |
| dispersion | RGB 色散 | 0 | 轻微（三通道 scale 差 ≈4–8%） |
| rim | 亮边（内发光） | 1px .22 + 8px .08 | 1px .32 + 10px .12 |
| saturation | 透射增饱和 | 1.4 | 1.6 |
| shadow | 接触阴影 | 弱 | 弱 |

两者共同约束：几乎不着色、亮边勾形、随背景变化、黑底与亮底都要验收。数值为初值，由样张 A 的实时滑杆校准。

**样张自查得到的两条修正（已采纳）**

- 液态玻璃若完全不散射（blur ≈ 0），压在复杂封面上时文字不可读 → 液态初值改为散射 3px、着色 12%：边缘负责"像玻璃"，中心负责"看得清"。
- **亮背景自适应加深**：环境变亮（浅色封面）时，玻璃自动增加约 22% 的中性压暗，保证白字可读；暗背景时恢复。这是光学材质必须有的规则，不是可选项。

**液态四组策展参数**（样张 A 的"四选一"，推荐「均衡」为默认）

| 版本 | 折射 | 色散 | 散射 | 亮边 | 着色 | 饱和 |
|---|---|---|---|---|---|---|
| 清透 | 22px | 4% | 1.5px | .50 | 8% | 1.6 |
| **均衡（推荐 / 默认）** | 30px | 6% | 3px | .55 | 12% | 1.7 |
| 浓郁 | 44px | 9% | 3px | .65 | 12% | 1.8 |
| 柔雾 | 18px | 3% | 8px | .45 | 10% | 1.5 |

### 6.3 星云与卡片

- **去掉相框**：封面本身就是卡片（圆角 14–16px），标题 / 歌手为卡片下方的无底文字，或仅在近中心 / hover 时出现。
- **景深**：近大远小 + 远处降亮降饱和（空气透视）；**焦点环内 `filter: none`**，模糊只留给外围。
- **当前播放卡**：由封面自身颜色形成的柔和环境光，而不是白色光晕。
- **Hover 动作沿用现有语义**：原地转正 + 放大 + 置顶 + 去模糊，**不发生位移**；只换材质（去掉白色光晕和相框）。样张 v1 曾因实现方式出现"hover 向右下方移动"，属样张 bug，已在 v2 修正，不是设计意图。

### 6.4 环境（背景）

- 近黑底（非海军蓝）+ 由当前封面采样的 3–4 团大面积柔光（缓慢气流漂移）+ 2–3% 胶片颗粒防色带。
- 环境光强度显著高于 GPT 母稿上限，但保留文字可读性闸门；浅色封面时降亮而非铺灰。
- 星点：大幅减少或改为带视差的稀疏尘埃。

### 6.5 歌词

- Z1 保留三身份运动逻辑，升级字的设计：当前句衬线 Display、候句更轻更小；已唱的字填满，正在唱的字用封面取色的单一强调色（可带极柔光——"正在演唱"是语义事件，符合发光权）。
- 漫游状态降低歌词存在感，聆听状态提升；与星云抢空间时以状态决定谁让位。

### 6.6 界面元素的状态语言

- Hover：图形 / 文字自身提亮（0.62→1.0）+ 图形微放大 ≤1.06；**无容器底、无光晕、无圆盘、无方框**；按下 0.94。
- 删除全局 `button:hover` 光晕规则；每个组件自带状态。
- 播放键：不用灰色实心圆，改为图形本身的强调（样张中给出备选）。
