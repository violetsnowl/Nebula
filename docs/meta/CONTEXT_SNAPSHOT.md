## 模型迭代与连续性（为什么这份文件存在）

- 底层模型可能随供应商版本迭代被替换；同一线程的上下文窗口也会被 **compaction** 压缩（官方说明：compaction 降低上下文体积、保留后续轮次所需状态，但压缩项是不透明摘要，细节会损失）。
- 连续性因此分三层：① 线程对话历史（会在压缩中损失细节）；② 仓库文档（本目录 + CHANGE_LOG + 冻结设计规格，人类可读、可无限增长）；③ git 提交历史（事实基准）。
- **协议**：新会话 / 新 agent / 换模型后按上面「恢复路径」读完再动手；重大里程碑或会话结束时刷新本文件「当前状态」小节。`AGENTS.md` 已配置自动指向这条路径。

  - 歌词：同一批 300 首里跨平台找不到同一录音的 362 → 99 首；网易云逐字过八成 74% → 85%；酷我 / 波点 93%；日语罗马音过八成 83%–98.9%；汽水歌有逐字 + 翻译（免授权）；和声 / 对唱在 QQ 等平台出声的歌上也有。
  - 剩下的都可归为外部原因：对方平台没有、两边歌词版本不同、平台不给数据（YouTube Music 歌词、酷我登录失效信号）、只能用会员账号确认（会员字段、酷狗第四路、酷我高音质）。
- 这一阶段用户拍板过的决定：
  - 先做歌词来源（2026-11-19）；「够好」按语种判（#197）；和声 A、对唱 C、换歌词 A（样张 L，#199 / #200）。

  - **「宁缺毋滥」放宽一档**（#205）：歌手子集 / 频道名 / 不同文字的歌手名也认，但排在完全一致的后面；以后再放宽先在真实候选上量化、人工核对。
  - 收尾轮「把列出的问题都做了」（#206–#214），包括日语本地读音词典（kuromoji，安装包多 17MB）。
