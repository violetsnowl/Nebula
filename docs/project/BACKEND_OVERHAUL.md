## 2. 用户问题与 A–N 核查结论

### 2.1 任务书 §4：用户可感知问题

1. **切歌慢：证实。** 原链路串行主源、多个候选和前端二次兜底，没有总期限。公开曲单原版单次最慢 22247ms，挑战集 23264ms。现在解析总预算 6000ms、后台权益快照、并发其他供流平台、缓存和单首预取。最终挑战集最慢 6007ms，7ms 为计时/调度开销。主源中位数 1 秒与兜底 4 秒目标仍未达到。
2. **概率失败和停住：证实部分根因。** 原版失败定时器依赖旧媒体的 `src/error`，有效旧 URL 会让跳歌条件不成立；重试又重复使用旧 URL。现改为独立失败状态、有限跳歌、强制新解析。平台可用率仍受匿名权益、接口响应与短预算影响；真实成功率没有提升，不能宣称彻底解决。
3. **信息和音频错位：证实并修复。** `loadTrack` 原先先发新元数据再等待取链，旧音频未停；迟到结果也不校验当前操作。现先暂停并卸载旧媒体、清空进度，再发布新歌加载状态；所有异步回写绑定代次。原生 Chrome 对照确认旧版取链时旧元素未暂停，整修后已暂停。
4. **“卡手”拆成三类测量。** 点击反馈：1600×900、1000 首演示库、cluster 舞台实际可见 14 张卡片，5 次点击后两帧时间 P50 为 11.1→11.0ms、P95 为 14.6→14.5ms。切换帧时间：P50/P95 两版约 6.1/6.2ms，无 >50ms JS long task；原版出现一次 66.5ms 帧间隔，无法凭短采样定位具体组件。播放缓冲：真实媒体未缓冲 seek、代理 Range/断流/关闭回收和 31 分钟恢复通过。**短时无头测量没有复现持续 UI 卡顿，也没有证明真实 CDN 不断续**；保留舞台与听音空间原代码，由主对话在目标机器补声卡与长时帧采样。
5. **清单外发现的问题。** QQ QRC 字段可能是数字开关，真正数据在加密 `lyric` 中；酷狗请求 `fmt=lrc` 实际拿不到 KRC；网易云混合 JSON/LRC 被旧解析器丢正文；两个歌词接口串行会丢掉已成功结果；探测短 Range 直接 destroy 破坏 keep-alive；Spotify 歌单新旧字段与分页不兼容。均已修正并加回归。

## 3. 任务书 §6：平台、歌词、翻译与封面

### 3.1 QQ 取链与实际音质

`src/main/adapters/qqAdapter.ts` 不再先请求已失效 express。缺媒体文件 ID 时查询 song detail，用 `file.media_mid` 构造 FLAC、320、128 文件名，批量向 musicu 获取 purl；登录时使用已有合法票据中的身份字段。回传音质按实际 purl 文件前缀确定，向下选档，不把缺失的 FLAC 伪装为 FLAC。匿名、权限不可用、连接失败在适配器中有区分，路由将可读原因送到前端现有位置。

离线契约 5/5 覆盖文件、身份、实际档位、降级、匿名失败。真实 `慌啥子嘛 / 村口吴老二` 在网易云超时后命中 QQ 相同录音，取链、音频签名探测均成功；这证明免费 QQ 链路至少有一次实际可用，**不证明绿钻/会员 FLAC 已恢复**。QQ 挑战 36 条主源均未成功，会员三档列入验收阻塞项。

### 3.2 兜底匹配与指定曲目

门禁先于打分：标题做 NFKC、少量繁简/假名等价处理，明确版本标签必须相同；艺术家全部集合相同；已知时长差不得超过 `max(2s, min(6s, 原时长×2%))`；缺时长时要求专辑相同。已核对别名包括椎名林檎、宇多田ヒカル、周杰伦、BTS。未掌握的译名和括注不宽松放行。feat 艺术家加入集合；Live、Remaster、伴奏、翻唱、Remix 等保留为版本约束。

116 个构造候选含 18 正例、98 负例；原规则接纳 113 个（15 正、98 负），新规则 18 正例全接纳、98 负例全拒绝。「丸ノ内サディスティック / オレンジ」相对于「椎名林檎」被歌手门禁拒绝。真实最终两组共有 1 次成功兜底，人工核对其标题、完整歌手、专辑、186 秒时长一致，规则亦通过；没有进行波形或听辨证明。**线上有效样本仅 1，不能报告可靠的线上误配率。**

### 3.3 逐字来源与不伪造原则

旧代码虽有 QRC/KRC 字段，实际 QQ 加密内容未正确解码、酷狗请求的是 LRC。现在 `parsers/timedLyrics.ts` 解码真实 QQ QRC 和酷狗 KRC，与网易云 YRC 汇入统一逐字格式。QQ QRC 的 DES 变体不能直接拿标准 Node 3DES 解；使用明确 MIT 授权的 qrc-decoder。KRC 使用真实 XOR/zlib 数据和原始逐字起止，不按字数分配时间。

前端 `src/lib/lyrics.ts` 只把正文一致且时间接近的真实逐字行并入；普通整句和没有单词时间的 JSON 不制造逐字。有逐字而普通 LRC 缺失时可由真实逐字正文生成句行。英文空格补齐不改变长音时长。

跨源歌词先经相同录音门禁，再要求至少 3 个不同正文锚点、覆盖至少 35% 的不同正文及至少一半时间跨度；只接受稳定整体偏移（绝对值≤8 秒、P95 残差≤180ms、最大残差≤500ms）。主源完全无正文时无法校准，兜底只返回整句并标 incomplete。没有接入未经版本与许可核对的 TTML 社区库，没有增加默认打开的实验来源。

### 3.4 翻译与罗马音

QQ 请求明确开启 trans/roma，使用正确 song ID；QRC 开关数字不能当歌词内容。QQ 逐字时间与翻译的 10ms 截断差通过同源≤80ms 合并解决。KRC 内嵌 language 数据提供译文/罗马音；网易云混合 JSON 元数据和 LRC 正文均保留，`lyric_new/lyric` 并发独立限时，某一个挂起不再丢失另一个已拿到的正文或翻译。

指定「丸ノ内サディスティック / 椎名林檎」的实际单曲检查：QQ `000xLw2D0E5Xjm` 得到 29 行正文、29 行逐字、29 行翻译，罗马音存在，1969ms；酷狗 `3E6C8D0999C51D1F52EF79E01FFBBBAF` 得到 29 行正文、29 行逐字、28 行翻译，1368ms。统计只记录行数和布尔值，未提交歌词原文。主源/增强 provenance、`romanRaw/romalrc` 带到 IPC，前端罗马音展示未新增。

旧增强问题并非只出在一个 if：QRC 未解码、网易云正文被丢、同源时间截断不匹配、弱录音匹配、长期旧缓存都会影响结果。schema 迁移、真实解码和匹配/时间轴条件一起修复。108 条挑战集翻译明显增加，100 条新榜单翻译由 73/75 降至 72/75，保留这个退步事实。

## 4. 新路由、接口和生命周期

### 4.1 音源路由

```text
用户点播/next/恢复
  → AudioPlayer 取消旧代次、暂停卸载旧源，发布新歌 loading
  → desktopPlayback.resolveTrackForPlay(requestId, forceRefresh)
  → IPC 每窗口登记可取消请求
  → SongResolver 地址缓存 / 共享进行中任务
  → 主平台取链 + 签名探测（优先保留原平台和录音）
  → 主源失败或仅试听：其他可供流平台并发搜索
      → 严格录音门禁 → 每平台最多 2 候选顺序取链/探测
      → 首个完整可播结果胜出，取消其他任务；只剩试听则保留试听标记
  → 当前本地代理端口包装 → 当前代次接管 Audio
  → playing 事件后置 playing=true；waiting 进入 loading
  → 失败：同歌一次强制刷新，随后有限跳歌或明确停止
```

主平台优先，账号权益排序作为后台快照参与兜底任务启动顺序；由于兜底平台并发竞速，**不是等待最高会员平台再回退**。最终实际供流 platform/sourceId/quality 通过 via 返回，音质与音源文案继续遵循 #120。Spotify、汽水只导入不供流；本地文件保持原始 file 路径。

| 解析总期限 | 6000ms，含全部阶段；不是每个平台分别 6 秒 |
| 主平台阶段 | 3500ms；其中取链 2300ms、探测 1600ms，继承剩余期限 |
| 其他平台 | 搜索 1600ms；最多 2 候选，单候选取链 2300ms、探测 1600ms，受父总期限约束 |
| 账号权益 | 初次游客快照立即返回；每 5 分钟后台并发刷新，各 2000ms |
| 请求取消 | 切歌/停止/窗口销毁；共享请求按引用计数，最后使用者取消才终止底层 |
| IPC | 每 webContents 独立 requestId；最多保留 16 个带 requestId 的活动请求；窗口销毁释放 |
| 媒体卡顿 | 10 秒保护、同歌一次强制重取、最多 6 首或队列长度的有限失败跳转 |
| 预取 | 剩余≤45秒时只准备下一首，`preload=auto` 不提前播放；插队/换队列失效 |
| URL 缓存 | 256 项，最长 2 分钟，与上游已知 expiresAt 取较短；到期前 5 秒失效 |
| 匹配缓存 | 512 项，24 小时，只存通过录音门禁的候选；账号变化/强制刷新逻辑隔离旧写入 |
| 探测缓存 | 2 分钟，Cookie 哈希区分身份；凭据变动清空 |
| 熔断 | 连续 3 次非超时、非取消异常后兜底跳过 30 秒；主源始终给恢复机会，单曲超时不代表平台宕机 |

请求上下文由 `src/main/requestScope.ts` 的 AsyncLocalStorage 传播，`HttpClient` 与网易云 Axios interceptor 继承 signal/deadline。账号刷新使用独立有界任务，不能因某首切歌取消而长期丢权益快照。网易云匿名初始化复用 24 小时内已有文件，桌面启动预热；不能把两首冷源的真实取链超时掩饰为“初始化完成就必能播”。

### 4.2 探测和代理

保留播放前探测，原因是 URL 或 audio MIME 不足以证明音频可用。探测只取前 512 字节并检查音频签名，拒绝伪装成 audio 的 HTML。明确完整长度的短 Range 等待响应 end，使 keep-alive 可复用；超量/未知长度才截断。3 次短探测回归新增连接数≤1。

`audioProxy.ts` 等待监听完成后返回 URL；旧代理 URL 仅解包后重新包装当前端口。支持 GET、HEAD、OPTIONS 和单 Range；逐跳验证协议与域名，按当前跳重新注入对应平台 Cookie/Referer，不把原平台 Cookie 搬到另一平台。最多 16 个活动请求。客户端切歌关闭立即 abort 上游，上游中断 destroy 下游，不永远挂起；退出时 dispose/关闭 Agent。实际断流、重定向、Range、关闭回收均有独立回归。没有测试全部音乐 CDN、全部 codec 的长期播放。

### 4.3 歌词路由和缓存

```text
实际供流身份（streamTrack/via）
  → v2 缓存命中
  → 主源歌词（3200ms）
  → 缺逐字/翻译：其余网易云/QQ/酷狗并发搜索（1800ms）
      → 严格录音门禁 → 每平台最佳候选取词（3200ms）
      → 按固定平台顺序合并，正文锚点验证整体偏移
  → 总期限 8500ms；部分成功可返回，取消后不写缓存
  → coverage/incomplete/provenance → 前端真实逐字规范化
```

只有主源正文可校准时才补跨源逐字；无正文时兜底降为整句。歌曲切走立即清空前一首歌词并取消 IPC，避免旧行短暂挂在新封面上。

磁盘缓存 schema=2，最多 500 项，读取文件上限 32MB；完整结果 30 天，不完整结果 6 小时；400ms 合并异步原子写。旧 schema 或无效字段失效。完整条件当前保守要求正文、逐字与翻译覆盖均足够（80%），不因“中文通常不需要翻译”而长期缓存半成品。

### 4.4 IPC 契约和前端对接

`src/main/types.ts`、`src/main/ipc.ts`、`electron/preload.cjs`、`src/lib/playlist/ipcClient.ts` 一致更新：

### 5.1 样本和测量口径

- **公开曲单组 100 条**：网易云公开榜单 `3778678`、`5059644681`、`2809513713`、`745956260` 各 25 条，分为华语/日语/英语/韩语榜单段。榜单分类不代表逐首人工语言识别；这些都是公开曲单元数据。权限提示 fee=1 的 54 条、fee=8 的 46 条，不能仅凭 fee 就认定当前账号无版权。

- 两个主要组共 208 条、201 个平台 ID；加额外案例共 **209 条、202 个平台 ID**。同首不同平台是独立来源记录，不宣称 209 首独立作品。公开数据可提交；没有私人歌单导出。

联网脚本并发 3、单步骤工具 watchdog 25 秒；总解析与歌词分别计时，不把歌词耗时混入音源耗时。不使用磁盘歌词缓存，URL/匹配缓存为进程内正常行为，未把所有歌曲预取一遍再算冷启动成绩。顺序跑冻结原版和整修版，不是随机双盲实验，网络/服务状态可能变化。

音源成功指取到并通过真实音频签名探测的地址；本组成功结果全部非试听。**这不是实际听完每首，更不是点击到声卡出声**。P50/P95 用 nearest-rank；仅在成功子集算成功延迟，失败另报；避免把大量快失败当作速度提升。

逐字同时报告 raw 字段存在与 usable：后者用当前测量器检查正文和逐字正文一致且时间≤250ms，至少一行才计有覆盖。对原版返回值也使用同一测量器重算；原版的 raw 16/19 并未等于 0，不能把重新算出的 usable=0 称为原版 UI 实测 0。

翻译覆盖为 `translatedLines / lyricLines ≥ 50%`，分母包含接口合并后的行；旧版可能存在只有翻译没有正文的孤立行，因此该指标只比较字段返回覆盖，不能直接等同用户看到的完整译文或音频对齐质量。逐字覆盖≥1行同样不代表整首全逐字；原始行数和 provenance 在证据中可查。

### 5.5 真实媒体、原生 Electron、长暂停

最终 Chrome 回归使用本地 2.4 秒 PCM WAV，固定解析延时 350ms、响应头延时 40ms。原版自然切歌 5 次为 403.3、408.3、418.1、403.5、403.7ms；整修后 0.2、0.3、0.1、0.1、0.3ms。前一轮 B7 同样观察到约 412–418ms→0.2–0.6ms，方向一致。两个版本都进行了相同受控测量；不能外推为真实跨 CDN 无缝播放认证。

真实媒体同时验证：取链时停旧音频、5 次连续点播最终歌曲、取链途中暂停、失败后恢复；乱序返回另由状态机测试覆盖。未缓冲 seek 使用 180 秒 WAV，起初只缓冲 16.002 秒，拖至 130 秒后观察到新的 Range 请求并继续播放；原版和整修版均通过，所以这项不是新修复的功劳。

31 分钟测试实际等待 1861652ms，旧 URL 在服务端过期后返回 403；恢复时重新解析，再 seek 80 秒，最终 currentTime=81.587728、playing=true、error=null，解析次数 2。该测试运行于 B6 的最终恢复逻辑；B8 仅增加失败文案传递与回归用例，不改过期判断。另有 B2 的一次真实 31 分钟通过。没有用修改系统时钟代替这两次等待。

Electron 43.3.0 的真实 main/preload、隐藏窗口、独立 userData 下，导入 1 个合成 12 秒 WAV，通过原生文件播放、seek>8 秒、真实 IPC 取消；最终 B8 再跑通过。只替换目录选择对话框输入和测试窗口启动设置，没有替换生产播放器或 preload。

### 5.6 迭代中失败过的结果

保留过程中的重要反证：第一轮整修 100 条样本曾出现 0 可播，原因包括把单曲超时累计为平台熔断、主源被熔断跳过、探测被过短阶段预算截断。B6 的 108 条中也只有 1 条成功。之后让主源始终可恢复、不把 timeout 视为整个平台故障、修复探测连接复用并调整阶段预算，最终为本报告表格。网易云歌词最后由串行改并发后，曲单翻译从一次中间轮的 67/75 恢复到 72/75。

这些变化不证明全部网络问题已解决；最终表格使用最后完整运行，没有挑历史最佳轮次冒充交付结果。最后 B8 改动只涉及失败文案与更多测试，没有改变最终联网采样使用的后端路由/解析逻辑，因此没有无意义地重跑 208 条并选更好数字。

## 10. 用户本机真实账号复测步骤

所有步骤使用凭据副本和测试profile，不改现有用户数据；仅保存脱敏统计。失败时记录 traceId、平台、stage、ms、outcome，不粘贴请求头或完整错误对象。

1. **QQ 普通/绿钻账号**：分别登录已获授权账号，用本人歌单至少20首（含免费、会员、FLAC可用/不可用）。请求128、320、FLAC，确认实际供流QQ、返回品质与文件一致；无高档则向下降级，不能假标签。退出/票据过期后提示需要登录；重新登录后缓存和权益应恢复。此项通过前不可宣布“QQ会员直取已修好”。
2. **网易云普通/VIP/SVIP**：各选可播放、无权限和试听曲目，检查标准/高音质/无损及已有高清臻音约定；试听不得标完整，能找到严格同录音完整源才切换。记录取链和探测各阶段，确认首次匿名预热不会阻塞首播。
3. **酷狗**：有效本人/公开歌单各一，检查导入的hash/albumID/封面，普通与VIP档位按正确hash取链；四条通道的失败应在预算内回收。当前公开3756318实际失败，不能当真实导入已经验收。
4. **Spotify**：OAuth有效授权，导入本人/可协作超过一页的歌单；核对总数和末尾歌曲，允许的空歌单与无条目权限必须区分。Spotify本身不供完整流，歌曲播放应走严格匹配的其他平台。保留权限失败，不绕过官方限制。
5. **汽水**：登录后导入一个真实歌单，核对数目及sourceId，播放由既有其他平台兜底。只验导入；不开发汽水取链。
6. **真实过期CDN**：QQ/网易云各一首，播放后暂停≥31分钟，再继续并拖到尚未缓冲的位置；应重取正确当前身份和品质、保留进度，无旧音频残留；含退出重开/插播会话恢复。
7. **线上录音与歌词人工复核**：指定椎名林檎、同名翻唱、Live、Remaster、合唱各至少3首。听辨歌手/版本，观察开头、中部、结尾的逐字/翻译同步；平台元数据通过不能替代这一步。
8. **国内网络速度与持续播放**：确认出口条件，运行随交付相同100+108公开样本及用户歌单；同时用声卡loopback测点击到首音、自然切换真实静音，分开冷首播/缓存命中。目标仍为主源中位≤1秒/P95≤2.5秒、兜底P95≤4秒、自然静音≤0.3秒。至少连续播放30分钟并记录帧/long task/媒体waiting，定位用户实际卡手环境。
9. **五入口操作**：在真实搜索页、歌手页、专辑页各点播一次，连续插播后回原队列；随机/单曲/顺序和插队末尾各走一遍。自动化已覆盖共享状态机，此处确认真实页面接线与账号数据。
