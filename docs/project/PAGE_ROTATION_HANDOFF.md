## 1. 用户要的是什么

用户原话（2026-11-25）要点：
1. 14 套大胆版式在真实歌曲上「落在段落上的分布规则合理吗？有没有明显的几个高概率出现、几个却很少出现？」结合各页的视觉语言气质，**重排段落切分与版式选择机制**，让它更合理、更符合各页气质与段落的配置。
2. 段落切分（`src/lib/listen/sections.ts`，前一个窗口写的）是版面的地基：是否最优？能否「更服务于版面预设」——太平就切细多换几页？切得不准就更准？太细就合并？

用户的工作习惯（见 `docs/meta/USER_PROFILE.md`）：**方向性改动先出可对比的样张让他用眼睛选，再动代码**；冻结规格（NEBULA_UI_SYSTEM）改动要他确认。第 0 / 1 步已修完，用户明确「做完这些再看第 2 步」。

## 2. 现在的机制（读代码前先看这里）

- 分页：`LyricPage.tsx` 里 `analyzeSong(els)` 出的 **句组（stanza）一页**，最多 `MAX_STANZA = 6` 句；`stanzas` 在段落内按时间空档切，>6 句在最大空档处对半切，孤句并邻组。
- 选版式：`src/components/lyric-page/pools.ts` 的 `pickTpl` + `PLAN`：
  ```
  verse:  ['held', 'c', 'foot', 'grid', 'c', 'c']
  pre:    ['spine', 'c', 'c']
  chorus: ['justify', 'register', 'bleed', 'corner', 'drum', 'c', 'c']
  bridge: ['diag', 'fault', 'c']   // flip(c) 时按歌换成 ['fault','diag','c']
  outro:  ['drum', 'groove', 'cut', 'c']
  ```
  `st.seen[kind]` **按「这种段落的第几页」计数**（不是第几次副歌），从计划表第 nth 格往后找第一套 `fits` 的；大胆版式一首最多一次、相邻不重复；`LOUD` / `NEW_O` 约束新四套不与大动作相邻；`lastChorus`（全曲最后一个副歌**段的第一页**）先试 `cut`（末句长音 ≥1.2s）再 `field`。
- 经典版式（`classic.ts`）是底子：每种段落一组，按页轮换。注意经典「右下斜体」id 已改为 `cornerR`（#278，原与大胆「转角」撞名）。

## 3. 真实数据审查结论（840 首，#278 前的代码；第 1 步只改版式外观与 fits 少量，结论仍成立，但**新窗口要先重跑一遍统计确认基线**）

数据：用户本机歌词缓存副本 500 首 + 会话曲库 397 首（带封面）匿名补歌词 → 840 首（中文 411、英文 316、日文 96、韩文 17）。

**切分形态**
- 每首中位 51 句、15 页；每页句数：1 句 8%、2 句 28%、3 句 16%、4 句 21%、5 句 14.5%、6 句 12%；每页中位 10 秒。
- 页按段落：主歌 35% / 副歌 39% / 桥段 10% / 尾声 8% / 预副歌 7%。含桥段的歌 53%、预副歌 39%、尾声 57.5%；56 首识别不出副歌（全按主歌）。
- 最长同段落连续页 p50 5、p90 10、最大 39（无副歌的歌）。

**分布问题（核心）**
1. **高潮倒置**：第一次副歌的页里 **70%** 是大胆版式，中间几次 **32%**，最后一次 **44%**。原因：`seen` 按页计数，第一次副歌的两三页就把 `justify / register / bleed / corner` 用光（满版齐行 665/682 次落在第一次副歌；出血大字 243 次在第一次、215 中间、30 最后——规格写的是「副歌第二次起」）。整首歌视觉高潮压在前面，后面变平。大胆版式前半 2647 次、后半 1819 次。
2. **冷热不均**（出现在多少首歌里）：满版齐行 81%、色场 70.5%、出血 58%、转角 57.5%（其中预副歌 244 次是撞名的经典 corner，真转角只在副歌）、一词放大 42%、斜线 39%、脚注 36%（中文 0%：竖排不排译文）、唱片纹 31%、稿纸 28%（英文 0%）、书脊 27%、**滚筒 15%、套印 11%、镂空 10%、断层 6%**。
   - 断层稀少原因：有桥段 447 首，第一页桥段恰好 3–4 句的只有 163 首，句长也合格（中 3–10 字 / 英 8–32 字母）的 63 首，再按歌对半轮流 → 约 50。
3. **主歌太平**：主歌页 80.6% 是经典版式；连续经典页 p50 4、p90 9、最大 44。

**切分问题**
- 副歌尾句边界：例《夜空中最亮的星》副歌末句「请指引我靠近你」被切成单句「主歌」页（p5 主2/3）。
- 大胆版式大多要 2–5 句（断层 3–4、转角 2–4、唱片纹 2–4、书脊 2–4），而 12% 的页是 6 句、14.5% 是 5 句 → 副歌 / 桥段长页挡掉了很多大胆版式。
- 无逐字时间、行与行之间空档为 0 的歌（如《旅行的意义》）句组只能靠 `MAX_STANZA` 对半切，切点不看语义。
- 署名行污染（已在 #278 修：265 首、493 页被名单占）——**第 2 步统计必须用 #278 之后的过滤重新跑**。

## 4. 前一个窗口的建议方案（未经用户确认，出样张让他选）

**A. 轮换按「第几次副歌」安排，整首能量递进**（最重要）
- 把 14 套按审查后的观感分三档能量：
  - 高能：满版齐行、回声滚筒、断层、错版套印、负形镂空、色场、出血大字；
  - 中能：转角、斜线、书脊、一词放大；
  - 静：稿纸、脚注、唱片纹（+ 经典版式）。
- 副歌按 `sec.occ / sec.of` 分「第一次 / 中间 / 最后一次」配额：第一次副歌给**一套中能或满版齐行**（不全用光），中间几次放套印 / 出血 / 滚筒（「副歌第二次起」回到规格原意），最后一次副歌放色场或镂空 + 再配一套，形成往上走的弧线。
- 每段（section）最多一套高能；任意两套高能不相邻（现在只约束了新四套，扩到全部高能）。
- 主歌：第一段主歌给一词放大 / 稿纸（中日韩）/ 脚注（有译文的横排），第二段主歌再给一套静或中能，避免连续经典 > 3 页。
- 桥段：断层 / 斜线照旧，但放宽断层 `fits`（2–5 句，或允许第二页桥段），让它不再只有 6%。
- 尾声：滚筒（反复短句）/ 唱片纹（≥2 句）/ 镂空（末句长音）。
- 冷门版式（镂空、滚筒）允许出现在中间几次副歌，但一首仍只用一次。

**B. 长期方向：内容驱动 + 能量曲线**
- 每页先算各版式的「契合度」：本页有重复短语 → 套印 / 滚筒；末字长音 → 镂空；强钩子词（#279 起歌名优先）→ 出血；3–4 句中等长度在桥段 → 断层；短促有力的句子 → 满版齐行；然后按 A 的能量曲线分配（例如从最重要的段落开始贪心：最后一次副歌 → 桥段 → 第一次副歌 → 其余）。
- 可以先只做 A，B 作为后续。

**C. 段落切分**（判断：**不需要整体切更细**，要更干净、更准、按段落定页长）
- 按段落定 `MAX_STANZA`：副歌 / 桥段 / 预副歌 ≤ 4 句，主歌 / 尾声仍 6 句（大胆版式多要 2–5 句）。
- 修副歌尾句边界：副歌块之后紧跟的一句若与其他副歌块的末句近似重复（或在其他副歌出现处也紧跟），并入副歌。
- 无逐字 / 空档为 0 的歌：句组切点优先选「句末标点 / 押韵 / 行长突变」而不是机械对半。
- 改完在 840 首上重跑统计，用数字确认（第一次 / 中间 / 最后副歌的大胆占比、各版式覆盖率、连续经典页、1 句页占比）。

**样张建议**：拿 3–4 首真实歌（中文竖排一首、英文横排一首、有桥段 + 多次副歌的各一首），把「现在」和「新机制」的整首页序（每页缩略 + 版式名 + 段落标签）并排排成一张可对比的页面（Artifact），让用户用眼睛选；参数类选择给 3–4 组策展候选 + 明确推荐。

## 5. 工具：怎么复现前一个窗口的数据与渲染（脚本在 `docs/project/page-rotation-kit/`）

**只用副本，不碰用户真实配置；数据、截图都不进仓库。** 在会话草稿目录建一个工作目录，把 kit 里的脚本拷过去，`data/` 放副本：
1. `data/lyric-cache.json`：复制 `%APPDATA%\music-nebula\lyric-cache.json`。
2. `data/ls/`：复制 `%APPDATA%\music-nebula\Local Storage` 整个目录（会话曲库在 LevelDB 里，按 UTF-16 存，日志块会切断 JSON，所以 `extract-tracks.cjs` 用正则逐条抠 `{"id":"平台:id","title":…,"cover":…}`）。
3. `node extract-tracks.cjs` → `data/tracks.json`；`node fetch-lyrics.mjs`（**匿名**空配置目录、只取歌词不取播放地址，3 并发约 1 分钟）→ `data/all-tracks.json`、`data/lyrics-fetched.json`。
4. 批量切分：`esbuild analyze-entry.ts --bundle --platform=node --format=cjs --outfile=analyze.cjs`（esbuild 在仓库 node_modules/.bin；入口按绝对路径 import 仓库里的 `normalizeLyricLines / toEngineLine / analyzeSong / songHook`，和 `LyricPage.tsx` 的处理链一致），再 `node run-analyze.cjs` → `data/shapes.json`、`data/lyrics-all.json`；`node shape-stats.cjs` 出切分形态统计；`node show-song.cjs 夜空中最亮的星` 打印单首的页 / 段落 / 版式。
5. 真实版式分配：`pnpm build` 后 `node harness.cjs stats` → `data/assign.json`（无头 Chrome 驱动构建产物：localStorage 注入会话曲库与 `stageMode: 'page'`、桌面 API 全部本地桩、歌词按键喂真实数据、读 `window.__nebulaLyricPage.pages()`；840 首约 15 分钟）；`node assign-stats.cjs` 出分布表。
6. 封面色系：`node cover-colors.cjs` → `data/colors.json`（`fam`：mono-dark / mono-light / vivid-* / pale-* …）。
7. 截图：`node pick-targets.cjs 4` 出目标（每套 × 色系 × 横竖排；英文歌缺封面时借同色系真实封面 `cover` 字段），`node harness.cjs shots targets.json`；越界审计：`node harness.cjs audit 25 <tag>`（读 `bounds()` 的 out / clash / bar / no）。
   - 环境变量：`NEBULA_HTML`（换构建目录，并行构建用 `npx vite build --outDir ../nebula-outputs-xx`）、`NEBULA_TPLS`（只审这几套）、`NEBULA_SHOTS`（截图目录）、`NEBULA_LOOSE=1`（shapes 与真实页数对不上时按真实页起点取时间）。

## 6. 踩坑（前一个窗口实测）

- **改了 `lyrics.ts` / 切分后，`shapes.json`、`assign.json` 立刻过期**：页数对不上，harness 会报 miss。每次改完重跑第 4、5 步。
- 静音音频要用 4000Hz 以上的 data URL：路由返回的不支持 Range、跳不了进度；blob 在 file:// 下播放失败；2000Hz 解码失败。（harness 已处理）
- 截图时机：先跳到目标时刻之前 W 秒再等 W 秒截，不要跳到点再等（会翻页，两页叠在一起）。
- 无头环境里负形镂空的镂空窗画不出跨域封面（桌面正常）。
- 仓库部分文件是 **CRLF**（如 `bold-b.ts`、`NEBULA_UI_SYSTEM.md`）：用 node 脚本按 `\n` 匹配替换会失败或拼坏，用 Edit 工具或先归一化换行再写回。
- 转场替身：版面任何「真字被另一份副本覆盖」的版式（色场的色块副本），转场替身都要跟着处理（#282）。
- QA：`pnpm qa` 逐套版式检查已含 `bar === 0 && no === 0`（#279）；新增版式或改排版后要过这一关。
- 用户决定：出血 / 套印 / 镂空 / 滚筒筒边行的大字可以沉到播放条玻璃后面（像水面倒影），审计不计；普通文字不行。

## 7. 验收口径（建议）

- 统计：第一次 / 中间 / 最后副歌的大胆占比应「递增」；14 套覆盖率不再出现 >75% 或 <10% 的极端（断层、镂空、套印、滚筒至少翻倍）；连续经典页 p90 ≤ 4；1 句页占比下降。
- 视觉：样张让用户选定后再落代码；落代码后用真实歌整首连拍（每页一张）给用户看页序。
- 每步 `pnpm build` + `pnpm qa` 全绿、独立提交，CHANGE_LOG 取号前重读顶部。
