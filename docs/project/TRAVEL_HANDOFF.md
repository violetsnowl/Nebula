## 1. 穿行是什么、为什么做

- 用户认为聆听时主舞台的表现力全压在歌词上，漫游歌词撑不起来，要做几种「聆听时的舞台」。样张 M（<https://claude.ai/artifact/CbkjKMV6sAxVuGfeaeFgNd>）对比了四种：漫游歌词现状 / 漫游歌词升级 / **穿行** / 版面。用户看完说「样张我都挺喜欢的，做吧」，按顺序做：漫游歌词升级（已完成）→ 版面（已完成、用户验收「完美」）→ **穿行（下一步，还没开始写代码）**。
- 穿行的一句话：歌词立在星云的纵深里，远处是下一句、下下句，唱一句就靠近一句，唱完从字中间穿过去；一路上的封面颜色从反差色慢慢走向这首歌自己的颜色，第一次副歌时「开进」它的颜色。
- 入口：和版面一样，作为舞台实验室（Ctrl+Shift+M）「聆听时的舞台」的第三个选项（`lib/space/lab.ts` 的 `stageMode`，现在是 `'roam' | 'page'`）。入口是否搬进「设置 › 聆听」还没定，问用户。

## 2. 样张 M 里的穿行（设计真源，坐标是样张的世界单位）

样张源码在旧会话草稿目录里，随时可能被清；以 artifact 为准（用 Artifact 工具 `read` 这个链接能拿到源码，看 `buildTravel` / `camAt` / `renderTravel` / `drawTravelLine`）。要点：

- **路线**：每句一个纵深位置 Z。相邻两句 +1000；换句组再 +450；中间是 ≥4s 的间奏再 +2800。路线本身是一条缓慢摆动的曲线 `pathX(z) = 260·sin(z/3100)`、`pathY(z) = 110·sin(z/2300 + 1.3)`。
- **句子摆位**：沿路线两侧三拍循环错开（偏移 (−180, 200) / (160, −110) / (−40, −420)），保证当前句、下一句、下下句在画面上至少上下错开约 70px，不叠字。
- **镜头**：每句开唱时镜头在离它 1100 处（缓入缓出地挪过去），唱到句尾推近到 720（匀速）；句与句之间从字中间穿过去。透视 F = 900，可见纵深 5400。
- **歌词**：只画当前句前一句到后两句（小曲库补偿时后五句当路标）；句子太长时世界字号缩小（≤60）。唱完正被穿过的那句淡得快些，不挡住接上来的当前句；候场的句子在间奏里变暗（× (1 − .6·间奏让位)）。逐字扫光同一套逐字层。
- **颜色旅程**：沿路每处想要的色相 = 这首歌的色相 ± 偏移：开头偏 160°（反差色），到第一次副歌的 Z 时平滑回到 0；之后副歌处 0、主歌 / 桥段处 55。每个封面位置挑颜色最接近目标的封面。背景径向渐变的色相也随这个进度从反差色走到封面色，段落开合（lift）越大越亮。
- **字照亮空间**：当前句是光源，附近封面按距离 `exp(−d/1000)` 叠一层 lighter 提亮。
- **卡片**：曲库里的封面沿路线均匀摆，每张离路线中心 380–1700（开方分布）、大小约 165–185。

## 3. 用户提出的顾虑：小曲库时旅程感不够（必须处理）

- 用户原话的意思：穿行的空间由歌曲卡片构成，当前歌单歌太少时卡片样本少，旅程感会大受限制。
- 样张里的实测（视野里同时看得见的封面数）：1400 首约 130 张、40 首约 4 张、12 首约 1 张。
- 样张里的「小曲库补偿」（300 首以下生效）：封面放大到 300–360、离路线更近（300–900）、按路段重复出现（每段每张出现一次，同一张不会同时出现两次）、前方多露出几句歌词当路标。开补偿后 40 首约 37 张、12 首约 10 张。
- 当时的结论（已告诉用户）：曲库几百首以上时穿行成立；几十首以下靠补偿只能保住「在往前走」，保不住「穿过一片星云」。真实实现时要再拿用户的真实小歌单看效果，必要时问用户小曲库时退回哪种舞台。

## 4. 落地时要沿用的东西（已经在代码里）

- **段落引擎** `src/lib/listen/sections.ts`：`analyzeSong` 给出段落 / 句组 / 间奏 / 第一次副歌，`stageAt(shape, lines, t)` 给出开合 lift 和间奏让位 gap——路线的 Z 间隔、颜色旅程、间奏变暗都靠它。
- **逐字层** `src/lib/listen/words.ts`：`renderUnits` / `measureUnits` / `waveOf` / `unitFrame` / `restUnit`。注意 `waveOf` 有可选参数 `widthK`（拉丁歌波宽系数）：听音空间和漫游歌词不传（=1），版面传 .6。穿行要不要单独调，等看了效果再问用户；**听音空间和漫游歌词的逐字层用户说「完美」，不要动**。
- **交接与常驻**：`lib/listenMode.ts`（`--lk`、`data-listen`、常驻聆听 `data-listen-pin`、`exit()`；常驻聆听下打开听音空间时底层舞台保持 `k = 1` 原地待命，硬阻断解除后自动恢复）；版面模式在 `<html>` 上写 `data-stage-mode='page'`，穿行可以照这个写 `'travel'`，styles.css 里星云在版面模式下的压暗规则可参考（注意加 `[data-lk]` 限定仅在聆听中生效，漫游态 `k = 0` 不压暗）。
- **漫游 ↔ 舞台 / 舞台 ↔ 听音空间的转场**：漫游 ↔ 版面用 `LyricPage.tsx` 的 `startMorph / stepMorph`；主舞台（版面 / 漫游歌词 / 底部字幕）↔ 听音空间已统一抽到共用引擎 `src/lib/listen/flyTransition.ts`（`LsFly`、`launchStageToListenFly`、`matchColumnLines`、`plainColumnText`、`isPageStageActive`，样式在 `src/components/listen/fly-transition.css`，旧 `lyric-page/toListen.ts` 已移除）。穿行接入听音空间双向一镜到底时直接复用 `flyTransition.ts`，切勿另写一套（注意更新 `isPageStageActive` 或扩为非漫游主舞台的统一接管判定，避免和 `LyricsLayer` 抢跑）。
- **测试探针的写法**：版面在 `window.__nebulaLyricPage` 上暴露了 probe / pair / pages / force / bounds / lsProbe；QA（`scripts/qa.cjs`）用它们量落位、越界和可见性。穿行也照这个做，QA 至少要量：替身落位、文字不出画面、帧耗时。

## 5. 实现方式的初步判断（还没和用户确认）

- 现在的星云舞台是 DOM 卡片 + 一层星点画布（`hooks/stage/useStage.ts`、`StageCanvas`），透镜景深是二维的，没有真正的纵深镜头。样张的穿行是一块 2D canvas：封面画成小图（sprite）按透视投影摆，镜头沿路线往前走。
- 建议沿用样张的做法：聆听且选了穿行时，在星云之上铺一层独立的 canvas（封面从曲库已有的封面缩略图取、缓存成小图），星云本身沉下去或隐藏；歌词用 DOM（逐字层要用 background-clip 扫光），按 canvas 同一套投影逐帧定位。这样不碰星云舞台的代码。
- 封面图来源、数量上限、内存（上千张缩略图）要先摸清楚；画布每帧只画视野内的。

## 6. 性能上已经踩过的坑（穿行一定会再碰到）

- **不要逐帧改根元素上的 CSS 变量**：星云有上千张卡片，`<html>` / `.app` 上的变量每变一次整棵页面重算样式（版面进听音空间那次，0.4s 的交接曲线让样式重算吃掉约 250ms）。
- **不要让大面积的滤镜参数逐帧变化**：星云的 blur 半径随 `--lk` 每帧变，整片星云每帧带虚化重画。
- **铺满全屏的 filter 层**（drop-shadow 之类）里有东西在动，整层每帧重算。
- 逐帧动画先集中读（getBoundingClientRect / getComputedStyle），再集中写，别读写交错。
- 用户说全软件的性能专项留到发布前单独做；穿行这一期只要保证自己的动画不掉帧。

## 8. 整合版（#287，2026-11-26）：怎么来的、和样张哪里不同

**两份初版的录屏对比**（用户 4 段录屏，绿色同一首、蓝色两边不是同一首；用户观察 + 抽帧 + 代码对照）：
- 初版 A（Claude）：停—推镜头，唱句时几乎静止、换句 1.15s 正弦缓入缓出，句间距 540。用户：「一脚油门一脚刹车」、纵深偏浅；颜色氛围更浓（严格按色相挑封面）。另：远处封面在画面中心挤成一团，三句歌词差不多亮，中间偏挤。
- 初版 B（Gemini）：句间距 1000（样张），唱句时匀速推一点，换句时目标瞬间跳到下一句、0.26s 指数追赶。用户：「快速穿梭」、纵深更深、封面稍稀、颜色氛围偏弱（每格从随机 36 张里挑、封面整体压得很淡）。另：中心封面压淡留出走廊，视觉焦点只有当前句，唱完的句子放大着飞出更像「穿过去」。
- 1495 首真实时间轴上量三种镜头：

| | A | B | 整合版 |
|---|---|---|---|
| 顿挫（每首最大加加速度，中位） | 49 万 | 1700 万 | 2.7 万 |
| 一句周期内最低速 / 最高速（0 = 停下再走） | 0.02 | 0.03 | 0.12 |
| 换句最快速度（单位 / 秒，每首中位） | 704 | 4515 | 941 |
| 下一句相对当前句的大小 | 0.65 | 0.53 | 0.58 |
| 唱一句当前句靠近多少（中段放大） | 1.11 | 1.17 | 1.27（有意，样张 1.53） |

**整合版取了什么**
- 镜头（两边都不用，重做）：先排目标轨迹——每句从离它 1250 缓缓靠近到 1000，换句时跨到下一句（有空档就在空档里匀速走完）——再对整条轨迹做 σ = 0.42s 的高斯平滑。速度、加速度处处连续，唱句时不停，换句只是平滑提一次速。参数在 `route.ts` 顶部；`buildRoute` 的 `tune` 参数只给调参脚本用。调参先在真实时间轴上量（顿挫、最低速 / 最高速、最快速度、开唱 / 唱完时句子大小），再看实物。
- 纵深：句间距 900、换句组 +250、间奏随长度最多 +2400、快句（两句开唱间隔 < 2.2s）按比例缩短（最少 55%）。
- 中心走廊（B）：封面透明度按离画面中心的距离从 .24 到 .76，画面中间不再挤成一团。
- 颜色（A）：整个曲库按色相分桶、每个位置严格挑色相最接近的封面（颜色旅程：开头反差 160° → 第一次副歌回到本色，之后副歌 0、其余 55°）；封面一次性柔化（`saturate .78 brightness .86`）、同一张专辑封面去重、压在歌词后面的封面按重叠面积压暗。
- 密度：取中，每 1/.018 ≈ 55 单位一张（A .022 偏密、B 约 .015 偏疏），视野里约 65–75 张。
- 歌词（B 的焦点 + A 的摆位）：当前句全亮，下一句 .58、下下句 .32，间奏里候场句再变暗；唱完的那句继续迎面放大、离镜头 800 起淡 380 淡尽（飞出画面是有意的，QA 只量没唱完的句子）；句子按「在参照距离时画面上的位置」三拍错开（窗口比例 (−.08, .20) / (.07, −.19) / (−.02, .018)），保证当前句、下一句、下下句上下错开约 80px；译文只在开唱后亮起；前方只露两句。
- 小曲库（A）：300 首以下封面放大到 250–290、离路线更近、按段重复；B 的分档与色雾微粒没采用（小曲库的退路待用户看实物定）。
- 进出只做淡入淡出（初版约定沿用）；`LyricsLayer` 只有三行让位判断，星云舞台、逐字层、一镜到底引擎都没改。
