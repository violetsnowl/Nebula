## 1. 穿行是什么、为什么做

- 用户认为聆听时主舞台的表现力全压在歌词上，漫游歌词撑不起来，要做几种「聆听时的舞台」。样张 M（<https://claude.ai/artifact/CbkjKMV6sAxVuGfeaeFgNd>）对比了四种：漫游歌词现状 / 漫游歌词升级 / **穿行** / 版面。用户看完说「样张我都挺喜欢的，做吧」，按顺序做：漫游歌词升级（已完成）→ 版面（已完成、用户验收「完美」）→ **穿行（#287 整合版已落地 main，2026-11-26 定为留，进入补全与优化阶段）**。
- 穿行的一句话：歌词立在星云的纵深里，远处是下一句、下下句，唱一句就靠近一句，唱完从字中间穿过去；一路上的封面颜色从反差色慢慢走向这首歌自己的颜色，第一次副歌时「开进」它的颜色。
- 入口：已于 #289 正式搬入「设置 › 聆听 › 聆听时的舞台」（三选一动态预览块：`漫游歌词 / 版面 / 穿行`），舞台实验室（Ctrl+Shift+M）保留快捷切换。

## 2. 样张 M 里的穿行（设计真源，坐标是样张的世界单位）

样张源码在旧会话草稿目录里，随时可能被清；以 artifact 为准（用 Artifact 工具 `read` 这个链接能拿到源码，看 `buildTravel` / `camAt` / `renderTravel` / `drawTravelLine`）。要点：

- **路线**：每句一个纵深位置 Z。相邻两句 +1000；换句组再 +450；中间是 ≥4s 的间奏再 +2800。路线本身是一条缓慢摆动的曲线 `pathX(z) = 260·sin(z/3100)`、`pathY(z) = 110·sin(z/2300 + 1.3)`。
- **句子摆位**：沿路线两侧三拍循环错开（偏移 (−180, 200) / (160, −110) / (−40, −420)），保证当前句、下一句、下下句在画面上至少上下错开约 70px，不叠字。
- **镜头**：每句开唱时镜头在离它 1100 处（缓入缓出地挪过去），唱到句尾推近到 720（匀速）；句与句之间从字中间穿过去。透视 F = 900，可见纵深 5400。
- **歌词**：只画当前句前一句到后两句（小曲库补偿时后五句当路标）；句子太长时世界字号缩小（≤60）。唱完正被穿过的那句淡得快些，不挡住接上来的当前句；候场的句子在间奏里变暗（× (1 − .6·间奏让位)）。逐字扫光同一套逐字层。
- **颜色旅程**：沿路每处想要的色相 = 这首歌的色相 ± 偏移：开头偏 160°（反差色），到第一次副歌的 Z 时平滑回到 0；之后副歌处 0、主歌 / 桥段处 55。每个封面位置挑颜色最接近目标的封面。背景径向渐变的色相也随这个进度从反差色走到封面色，段落开合（lift）越大越亮。
- **字照亮空间**：当前句是光源，附近封面按距离 `exp(−d/1000)` 叠一层 lighter 提亮。
- **卡片**：曲库里的封面沿路线均匀摆，每张离路线中心 380–1700（开方分布）、大小约 165–185。

## 3. 用户提出的顾虑：小曲库时旅程感不够（必须处理）

- 用户原话的意思：穿行的空间由歌曲卡片构成，当前歌单歌太少时卡片样本少，旅程感会大受限制。
- 样张里的实测（视野里同时看得见的封面数）：1400 首约 130 张、40 首约 4 张、12 首约 1 张。
- 样张里的「小曲库补偿」（300 首以下生效）：封面放大到 300–360、离路线更近（300–900）、按路段重复出现（每段每张出现一次，同一张不会同时出现两次）、前方多露出几句歌词当路标。开补偿后 40 首约 37 张、12 首约 10 张。
- 当时的结论（已告诉用户）：曲库几百首以上时穿行成立；几十首以下靠补偿只能保住「在往前走」，保不住「穿过一片星云」。真实实现时要再拿用户的真实小歌单看效果，必要时问用户小曲库时退回哪种舞台。

## 4. 落地时要沿用的东西（已经在代码里）

- **段落引擎** `src/lib/listen/sections.ts`：`analyzeSong` 给出段落 / 句组 / 间奏 / 第一次副歌，`stageAt(shape, lines, t)` 给出开合 lift 和间奏让位 gap——路线的 Z 间隔、颜色旅程、间奏变暗都靠它。
- **逐字层** `src/lib/listen/words.ts`：`renderUnits` / `measureUnits` / `waveOf` / `unitFrame` / `restUnit`。注意 `waveOf` 有可选参数 `widthK`（拉丁歌波宽系数）：听音空间和漫游歌词不传（=1），版面传 .6。穿行要不要单独调，等看了效果再问用户；**听音空间和漫游歌词的逐字层用户说「完美」，不要动**。
- **交接与常驻**：`lib/listenMode.ts`（`--lk`、`data-listen`、常驻聆听 `data-listen-pin`、`exit()`；常驻聆听下打开听音空间时底层舞台保持 `k = 1` 原地待命，硬阻断解除后自动恢复）；版面模式在 `<html>` 上写 `data-stage-mode='page'`，穿行可以照这个写 `'travel'`，styles.css 里星云在版面模式下的压暗规则可参考（注意加 `[data-lk]` 限定仅在聆听中生效，漫游态 `k = 0` 不压暗）。
- **漫游 ↔ 舞台 / 舞台 ↔ 听音空间的转场**：漫游 ↔ 版面用 `LyricPage.tsx` 的 `startMorph / stepMorph`；主舞台（版面 / 漫游歌词 / 底部字幕）↔ 听音空间已统一抽到共用引擎 `src/lib/listen/flyTransition.ts`（`LsFly`、`launchStageToListenFly`、`matchColumnLines`、`plainColumnText`、`isPageStageActive`，样式在 `src/components/listen/fly-transition.css`，旧 `lyric-page/toListen.ts` 已移除）。穿行接入听音空间双向一镜到底时直接复用 `flyTransition.ts`，切勿另写一套（注意更新 `isPageStageActive` 或扩为非漫游主舞台的统一接管判定，避免和 `LyricsLayer` 抢跑）。
- **测试探针的写法**：版面在 `window.__nebulaLyricPage` 上暴露了 probe / pair / pages / force / bounds / lsProbe；QA（`scripts/qa.cjs`）用它们量落位、越界和可见性。穿行也照这个做，QA 至少要量：替身落位、文字不出画面、帧耗时。

## 5. 实现方式的初步判断（还没和用户确认）

- 现在的星云舞台是 DOM 卡片 + 一层星点画布（`hooks/stage/useStage.ts`、`StageCanvas`），透镜景深是二维的，没有真正的纵深镜头。样张的穿行是一块 2D canvas：封面画成小图（sprite）按透视投影摆，镜头沿路线往前走。
- 建议沿用样张的做法：聆听且选了穿行时，在星云之上铺一层独立的 canvas（封面从曲库已有的封面缩略图取、缓存成小图），星云本身沉下去或隐藏；歌词用 DOM（逐字层要用 background-clip 扫光），按 canvas 同一套投影逐帧定位。这样不碰星云舞台的代码。
- 封面图来源、数量上限、内存（上千张缩略图）要先摸清楚；画布每帧只画视野内的。

## 6. 性能上已经踩过的坑（穿行一定会再碰到）

- **不要逐帧改根元素上的 CSS 变量**：星云有上千张卡片，`<html>` / `.app` 上的变量每变一次整棵页面重算样式（版面进听音空间那次，0.4s 的交接曲线让样式重算吃掉约 250ms）。
- **不要让大面积的滤镜参数逐帧变化**：星云的 blur 半径随 `--lk` 每帧变，整片星云每帧带虚化重画。
- **铺满全屏的 filter 层**（drop-shadow 之类）里有东西在动，整层每帧重算。
- 逐帧动画先集中读（getBoundingClientRect / getComputedStyle），再集中写，别读写交错。
- 用户说全软件的性能专项留到发布前单独做；穿行这一期只要保证自己的动画不掉帧。

## 8. 整合版（#287，2026-11-26）：怎么来的、和样张哪里不同

**两份初版的录屏对比**（用户 4 段录屏，绿色同一首、蓝色两边不是同一首；用户观察 + 抽帧 + 代码对照）：
- 初版 A（Claude）：停—推镜头，唱句时几乎静止、换句 1.15s 正弦缓入缓出，句间距 540。用户：「一脚油门一脚刹车」、纵深偏浅；颜色氛围更浓（严格按色相挑封面）。另：远处封面在画面中心挤成一团，三句歌词差不多亮，中间偏挤。
- 初版 B（Gemini）：句间距 1000（样张），唱句时匀速推一点，换句时目标瞬间跳到下一句、0.26s 指数追赶。用户：「快速穿梭」、纵深更深、封面稍稀、颜色氛围偏弱（每格从随机 36 张里挑、封面整体压得很淡）。另：中心封面压淡留出走廊，视觉焦点只有当前句，唱完的句子放大着飞出更像「穿过去」。
- 1495 首真实时间轴上量三种镜头：

| | A | B | 整合版 |
|---|---|---|---|
| 顿挫（每首最大加加速度，中位） | 49 万 | 1700 万 | 2.7 万 |
| 一句周期内最低速 / 最高速（0 = 停下再走） | 0.02 | 0.03 | 0.12 |
| 换句最快速度（单位 / 秒，每首中位） | 704 | 4515 | 941 |
| 下一句相对当前句的大小 | 0.65 | 0.53 | 0.58 |
| 唱一句当前句靠近多少（中段放大） | 1.11 | 1.17 | 1.27（有意，样张 1.53） |

**整合版取了什么**
- 镜头（两边都不用，重做）：先排目标轨迹——每句从离它 1250 缓缓靠近到 1000，换句时跨到下一句（有空档就在空档里匀速走完）——再对整条轨迹做 σ = 0.42s 的高斯平滑。速度、加速度处处连续，唱句时不停，换句只是平滑提一次速。参数在 `route.ts` 顶部；`buildRoute` 的 `tune` 参数只给调参脚本用。调参先在真实时间轴上量（顿挫、最低速 / 最高速、最快速度、开唱 / 唱完时句子大小），再看实物。
- 纵深：句间距 900、换句组 +250、间奏随长度最多 +2400、快句（两句开唱间隔 < 2.2s）按比例缩短（最少 55%）。
- 中心走廊（B）：封面透明度按离画面中心的距离从 .24 到 .76，画面中间不再挤成一团。
- 颜色（A）：整个曲库按色相分桶、每个位置严格挑色相最接近的封面（颜色旅程：开头反差 160° → 第一次副歌回到本色，之后副歌 0、其余 55°）；封面一次性柔化（`saturate .78 brightness .86`）、同一张专辑封面去重、压在歌词后面的封面按重叠面积压暗。
- 密度：取中，每 1/.018 ≈ 55 单位一张（A .022 偏密、B 约 .015 偏疏），视野里约 65–75 张。
- 歌词（B 的焦点 + A 的摆位）：当前句全亮，下一句 .58、下下句 .32，间奏里候场句再变暗；唱完的那句继续迎面放大、离镜头 800 起淡 380 淡尽（飞出画面是有意的，QA 只量没唱完的句子）；句子按「在参照距离时画面上的位置」三拍错开（窗口比例 (−.08, .20) / (.07, −.19) / (−.02, .018)），保证当前句、下一句、下下句上下错开约 80px；译文只在开唱后亮起；前方只露两句。
- 小曲库（A）：300 首以下封面放大到 250–290、离路线更近、按段重复；B 的分档与色雾微粒没采用（小曲库的退路待用户看实物定）。
- 进出只做淡入淡出（初版约定沿用）；`LyricsLayer` 只有三行让位判断，星云舞台、逐字层、一镜到底引擎都没改。

**还没做的**：从当前星云长出纵深的进出（或与用户对齐的新进出方案）、和听音空间的双向一镜到底、间奏三点与取词加载三点、改窗口大小时重排路线、以及用户待融入的观感优化（规格写进 `NEBULA_UI_SYSTEM.md` §7.1c 后删本文件）。入口已于 #289 进「设置 › 聆听」。

## 9. 空间歌词（穿行第二版）设计稿（2026-11-27，待用户确认后开工）

> 来源：用户 2026-11-26 的五张 Demo 图（原图 `C:\Users\LIU\Pictures\Screenshots\Screenshot 2026-11-26 192848.png` 上改的）、Claude 与 Gemini 各自的分析、Gemini 两版仓库外样张（`C:\Users\LIU\.gemini\antigravity\brain\4f7303ef-…\travel-spatial-v2.html`，用户不满意，改由 Claude 在本仓库原生实现）。
> 用户要的一句话：穿行里的歌词不再是正对镜头的平面字幕，而是在星云封面之间穿行、缠绕，有真正的空间感、设计感和张力。

### 9.1 v2 样张为什么不行（2026-11-27 用无头 Chrome 硬件渲染实播两首歌、四种模式、各段落每 0.5 秒截帧看过）

1. **字不是主角**：当前句只占画面宽约 25–30%（Demo 图里 45–55%），下一句、下下句缩到十几像素，读不清。
2. **每句一样**：编舞模式下同一段里每句都是同一个动作（一条新丝带从左边一张封面出发 → 唱完从左下飞走），8 秒看不到变化；丝带不连续，每换一句凭空出现一条新的。
3. **丝带像绶带**：铜棕实心带加双金边，压在字后面像奖状绶带，中文尤其明显；不是 Demo 1 那种近乎透明的玻璃。
4. **封面是一堆乱撒的卡片**：全屏均匀撒满，每张随机倾斜、亮度一样，没有中心走廊，也没有远近层次；画面一直又满又碎，和字抢。不少封面发白像底片。
5. **和封面的关系是摆拍**：「主角封面」只是放在丝带起点，丝带没有真的绕它、穿它；偶发的遮挡反而压在正在唱的字上（违反可读性底线）。
6. **星图 / 星环像示意图**：短语散在全屏四角，眼睛满屏找下一截；连线横穿全屏；三道细白环像原子图标；中文按字数硬切（「都是最 / 美的瞬间」）。
7. **没有光**：Demo 1 的暖光焦点、字照亮附近封面、#287 的颜色旅程都没了，背景近黑、发闷。
8. 「现状」对照组是它重写的一个小字版本，不是软件里真实的穿行，比较失真。

### 9.2 原则（开工前锁定）

- **字是主角**：当前句在屏幕上占窗口宽 45–60%（长句拆成两段走弯，见 9.3），衬线大字；下一句约 0.55 倍且能读，下下句约 0.32 倍可辨（沿用 #287 的焦点层级）。
- **一条连续的路**：整首歌写在同一条空间曲线上，句与句是同一条路的前后段；换句时镜头沿路滑过去，不跳切、不凭空出现。
- **结构先于材质**：路平时看不见（只有字），需要时才显形成一根极淡的光丝；不用实心缎带。玻璃带只作为高潮的材质招式，而且要透明到只剩折射和边缘光。
- **封面有秩序**：封面排成沿路的「隧道壁」，朝向路、有规律地内倾，中心留走廊；近处少而大、远处多而小；可见数量和 #287 相当（约 60），不再满屏。
- **招式少而准**：一首歌大招 4–6 次，只放在段落要害；其余句子只做「路」的基本动作。相邻两句不连着出大招。
- **光有语义**：只有正在唱的位置是光源（照亮字和附近封面），没有装饰性光斑、粒子爆、HUD 刻度、反光斑。
- **可读性底线（Z1 硬约束）**：正在唱的词永远不被挡、不出反字、倾斜有上限；下一句提前能读；招式只作用在还没唱和已经唱完的部分。

### 9.3 基本语法（每一句都有）

- **路**：沿用 #287 的镜头路线（目标轨迹 + 高斯平滑，已在 1495 首真实时间轴上量过不顿挫）。每句在路上有锚点（沿用三拍错开的摆位），句子本身是过锚点的一小段曲线，相邻两句的段之间用平滑曲线接起来，整首连成一条路。
- **字贴着路**：每个字是一块独立的小平面，沿路排开（排版软件里的「路径文字」：字本身不变形，只沿曲线摆放和转向），所以字会随路弯、随路透视变小，但笔画永远干净。
- **转正**：句子在远处时可以侧着（偏航最多约 50°、滚转最多约 20°，像 Demo 1 里拐向远处的「it's a prison inside my mind」）；靠近、开唱前平滑转正：开唱时偏航 ≤ 25°、滚转 ≤ 12°、弯曲的拱高 ≤ 句长 6%。（2026-11-27 用户看过动态后改：以句首为轴、开唱前 2.4–0.3 秒间慢慢转过来，开唱前已经停稳，见 §9.9 第二步修订。）
- **句形**（2026-11-27 用户反馈「只有下凹和下拱两样，单调、单看也没设计感」后补，从五张 Demo 图提炼）：每句是五种句形之一——**斜坡**（斜着往纵深爬，Demo 1 / 5 的「it's a prison inside my mind」）、**波**（一整个 S，Demo 2 上句）、**扬尾**（前半平、句尾扬起，Demo 2 的「…three strikes」）、**拐角**（句尾越来越往远处拐进去，Demo 1 的「I need you to free me」）、**弧**（绕走廊的一段圆弧，上方 ∩、下方 ∪、两头往远处收，Demo 4 的环带）。方向统一「往画面中心收」：下方的句子往上弯、上方的往下弯，像整首歌都卷向隧道里。开唱时保留约一半的形（不压平）；局部倾角有上限：整体滚转 ≤ 约 15°，正在读的字最多斜约 35°（只在扬尾的最后几个字），拐角句尾往远处转约 50°。分配见 §9.9。
- **长句拆成两段**：屏幕放不下的长句，在词与词之间最长的停顿（或标点、中文空格）处拆成两段，路在两段之间拐一个弯（Demo 1 把一句拆成「I need you to free me」/「it's a prison inside my mind」）。不在词中间拆，中文不在两字词中间拆。
- **唱完掠过**：唱完的句子继续迎面靠近，从镜头侧边滑出画面，越近越虚（景深）；不在画面正中糊住接上来的当前句。
- **光点**：正在唱的字的位置有一个很小、很柔的光点（字色），沿路跟着演唱移动；它照亮附近的封面（取代 #287 的整片提亮）。
- **光丝**：~~当前句与下一句之间的那段路显形成一根很淡的光丝（约 1px，透明度 .12–.25），告诉眼睛下一句在哪；更远的路不画。~~ 2026-11-27 用户看过动态后取消常驻光丝（像隧道里的蛛丝，配合转正像把句子扯直），改为**光的飞行**：一句唱完，光点沿平缓弧线飞到下一句句首，身后一截很快收拢的光尾，到了停在句首等开唱（见 §9.9 第二步修订）。
- **衬托层**（2026-11-27 用户：「每句都孤零零裸漂在空间里；五张 Demo 的字都被光效衬托着，做一些淡淡的气流、光带，不夺睛不吵闹的层次」）：仍然不做实心带和玻璃板，只取 Demo 里衬托的「气」。全部取封面色、叠加，不挡字也不挡封面；平时很淡，只有正在唱的位置把它们点亮（光有语义）。当前句满强度，下一句约 0.35（提示下一句在哪），唱完掠过时淡出。

  - **光雾**：当前句底下一层很宽很淡的柔光，像字把周围的空气照亮（Demo 4）。
  - **浮尘**：二三十粒极小的尘顺着气流飘、闪；靠近正在唱的位置时被照亮（Demo 2 / 4 沿带的微粒）。
- **译文**：跟在原文下方、沿同一条路，开唱后才亮（沿用 #287）。
- **逐字层不变**：扫光、波浪、长音放大和白光、尾韵的时间与幅度直接调用现有逐字层（`words.ts` 的 `waveOf` / `unitFrame`，只调用不改），只是换成在 3D 里画；颜色模式（封面色 / 同色系）、字体（衬线 / 无衬线）、粗体、译文开关全部沿用设置。

### 9.4 招式（只在要害处出）

| 招式 | 样子 | 用在哪 | 可读性怎么保 |
|---|---|---|---|
| **穿针** | 路从近处两张封面之间、从其中一张背后穿出来；字在封面背后的那一截，封面在字经过的地方变成透明玻璃（折射 + 轻微色散，即已认可的液态玻璃），字透出来 | 第一次副歌的第一句；桥段后回到副歌的第一句 | 开唱时正在唱的词已经绕到封面前面；只有没唱的部分在封面后 |
| **环** | 句子绕成一个倾斜约 15–20° 的环套在一张近处的主角封面上，前半环在封面前、后半环在封面后；环随演唱转动，正在唱的词始终转到正前方最低倾角处；唱完环松开、拉直成路通向下一句 | 短的钩子句（拉丁 ≤ 28 字符 / 中日韩 ≤ 9 字），或句末有长音的短句 | 背面朝外的字直接隐去，不出反字；~~环的周长约为句长 1.15 倍~~ 字只占环正面约 140°（周长约句长 2.6 倍，1.15 倍时短句的环直径只有两三个字宽，正面只露两三个字），唱的时候只在句子中间那段跟着转，正在唱的字始终在正前方 ±20° 内 |
| **卷起** | 路在进入这句之前打一个大螺旋，镜头沿螺旋穿过去，沿途 6–10 张封面被带着绕路转一段（像被气流卷起），唱完 1 秒内回到原位 | 第二次及以后副歌的第一句，或全曲最高能的一句 | 螺旋只在「进场」那段路上；句子本身停在螺旋出口，是正的 |
| **立起** | 下一句先平躺在路面上（像公路标线字，俯仰约 55°，透视下仍能读），唱到哪个词，哪个词立起来朝向你（轻微弹性，适度果冻感） | 节奏密的主歌句（快歌密度高） | 开唱的词已经立起；平躺的只是还没唱的词 |
| **星座** | 句子按停顿拆成 2–3 截，挂在路旁几张封面边上（都在画面中央 60% 的框内），唱到哪截那截亮起，一根细线从上一截画到这一截；唱过的线淡淡留在身后 | 前奏后第一句、间奏后、安静的桥段句、尾声 | 一句最多 3 截，按语义断开，最短 2 个中文字 / 1 个英文词；拆不开的句子回到普通的路 |

**明确不做**（来自 Demo 图但和既定审美冲突）：粉色金属立体厚字（Demo 2）、HUD 小字与刻度线（Demo 3）、粒子爆裂与烟花（Demo 3）、背面反字（Demo 4）、大面积辉光 / 霓虹光带（Demo 3、4）、蝴蝶花纹与玻璃碎屑（Demo 5）、星球等无语义装饰。Demo 5 的「整句压在一块玻璃板上」留作以后的可选材质，第二版不做。

### 9.5 编舞（每首歌一份固定的分配，像版面的轮换）

- 输入：段落（类型、第几次、开合）、句长与时长、长音、快歌密度、间奏，以及**重复句**（同一句文字出现 ≥ 2 次）。
- **不能只信段落识别**：真实数据里段落识别会漏（《再见》第一次副歌「不要对我说再见一句再见」被算进主歌）。所以副歌入口同时看「重复句第一次出现的位置」和开合。
- **重复的钩子句**：同一句每次出现用同一个招式，让耳朵和眼睛都认得出；越往后的副歌幅度越大、左右镜像交替。同一段里第 4 次以上的同一句（《3 Strikes》的「-Don me…」一首歌出现约 30 次）退回普通的路，只保留左右交替，避免累。
- 预算：大招（穿针、环、卷起）每 4 句最多 1 个、全曲 4–6 个、相邻两句不能都是大招；中招（立起、星座）不超过全部句子的一半。
- 时长下限：短于 1.2 秒的句子（如 0.8 秒的「Like I got three strikes」）不承担任何招式。
- 同一首歌每次播放编舞相同。
- 落代码前先用 1495 首真实歌词量分布（各招式占比、相邻大招、短句误用），和版面轮换的做法一样（NOTES「调轮换不用每次整页渲染」）。

用两首样张歌试排（示意，最终以规划器实际输出为准）：
- 《3 Strikes》：开头 0–3 四遍「Down for one night…」→ 第 1 遍星座，其后普通的路；第一个「-Don me」段（4–7）→ 第 4 句环（钩子句第一次），其余普通；主歌 8–11 → 立起；预副歌 12–16 → 13（「I need you to free me / it's a prison inside my mind」长句拆两段）普通的路但走大弯，16 句末长句进副歌；副歌 17 → 穿针；第二次副歌 22 → 卷起；桥段 27–30 → 星座；之后各次副歌入口（36、41、47）交替环 / 卷起；结尾 55–59 五遍「Like I got three strikes」（每句 1.5 秒）普通的路、左右交替，最后一句星座收尾。
- 《再见》：0「爱情的起点」星座；1「都是最美的瞬间」（句末长音「间」）环；主歌 2–7 普通 / 立起交替；8「不要对我说再见一句再见」（重复句第一次）穿针；15「能不能再见」（长音）环；24 第二次「不要对我说再见」卷起；39「反正睡醒是新的 一天」（18 秒长音）星座；40 第三次「别对我说再见」卷起（更大）；50–51 尾声星座。

### 9.6 封面空间

- **隧道壁**：封面沿路排布（位置分布沿用 #287：离路线 380–1700、按色相挑），但每张朝向路的中轴、按离路线的远近有规律地内倾 12–28°（越外圈越斜），形成 Demo 1 那种隧道壁，而不是随机角度。
- **层次**：近处（离镜头 < 700）少而大、带景深虚化；中景清楚；远处小、渐渐融进背景色（沿用 #287 的淡出曲线）。
- **走廊**：画面中心的封面压淡（沿用 #287 的 .24 → .76），当前句背后的封面按重叠压暗（沿用）。
- **材质**：封面即卡片、无相框；只加一圈很细的内侧亮边（液态玻璃已认可的「内侧亮边」），圆角沿用。
- **主角封面**：招式需要的封面从路附近挑颜色最接近目标色相的那张，放大约 1.4 倍、挪到路边。
- **颜色旅程、背景渐变、段落开合变亮**：全部沿用 #287。
- **小曲库**：沿用 #287 的补偿（放大、靠近、按段重复）；隧道壁让少量封面也能围出空间感。是否退回别的舞台，等第二版做出来用真实小歌单再看。

### 9.7 技术方案

- 穿行改成一张 WebGL2 画布：封面、路、光丝、字都在同一个三维空间里，前后遮挡按真实深度（用户在 Gemini 窗口已同意走真 3D）。不引入 three.js 之类的新依赖，自己写（封面与字都是成批画的小平面，外加光丝和一个景深 / 玻璃的后处理）。
- 字：用软件现有字体（Newsreader / 系统中文衬线等，和其他歌词处同一字体栈）在内部画成字形贴图，每个字一块平面；所以中日韩字形和其他界面一致。
- 帧耗时：QA 现有「穿行 p95 < 6ms」继续有效；WebGL2 不可用时自动回退到 #287 的画布版本。
- 开关：第二版先挂在舞台实验室（Ctrl+Shift+M）的隐藏开关「穿行 · 空间歌词（实验）」下；设置里的「穿行」仍是 #287，直到用户验收通过再替换。
- 不改：`words.ts`、`engine.ts`、星云舞台、版面、漫游歌词。
